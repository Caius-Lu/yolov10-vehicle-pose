# Vehicle Pose 压缩/剪枝实验总结

受众：算法工程师  
范围：PyTorch 模型压缩/剪枝，不使用 TensorRT  
评估：RTX 3090 Ti，640，batch=1，one-to-one-only，Conv/BN fuse，FP16，
paired AB/BA 延迟；精度基于 CarFusion 验证集 3,606 图、11,569 实例。

精度准入线：Box mAP50-95 ≥ 0.64761，Pose mAP50-95 ≥ 0.49455。  
延迟准入线：相对原始完整 baseline 至少下降 10%。

原始 baseline：Box/Pose 约 0.665/0.515。部署 fuse+FP16 后为
0.665/0.514，延迟 7.147→5.727 ms，下降 19.88%。

主要实验：

- 512 蒸馏：0.633/0.474；7.001 ms，比 640 的 6.905 ms 更慢。
- e=0.4375+Head96：快 10.81%，参数 -12.65%，恢复后约 0.476/0.262。
- 通道结构化剪枝：参数最多下降约 52%，延迟无收益，部分精度接近零。
- BN-scale 稀疏训练：0.661/0.512，但没有形成足够零通道；物理剪枝失败。
- 检测塔 depth=1：快 11.915%，最好约 0.633/0.474。
- 删除 P3 C2f bottleneck：快 10.56%，最好约 0.634/0.460。
- 姿态塔+分类塔 depth=1：快 15.47%，最好约 0.580/0.366。
- 分类塔 depth=1：64/96 通道快 12.26%/12.01%，最好约
  0.610/0.452、0.61831/0.45890。
- ClassLite48：快 12.952%，最好约 0.61932/0.46186。
- ClassLite56：快 9.85677%，未过 10% 门槛。
- ClassLite52：6.02302→5.38792 ms，快 10.54459%，fused 参数
  3,821,186；最好 0.62507/0.46795，速度通过、精度未通过。
- 删除 one-to-many 部署分支：参数 -26.96%，文件 -26.59%，模型加载显存
  -11.22%，峰值显存 -8.99%，输出逐元素一致；精度 0.665/0.514，延迟仅快
  0.19%。

关键结论：

1. 参数减少不是 GPU 延迟的可靠代理，减少串行 kernel 才有效。
2. 分类置信度同时影响 Box 和 Pose mAP，分类塔是当前主要精度瓶颈。
3. 简单 tensor slicing 破坏通道语义；投影折叠、定向搬运、padding 热启动可靠。
4. 选择性训练必须冻结 BN running statistics。
5. 当前任务中纯监督头部恢复优于异构教师 KD。
6. 最成熟成果应拆分交付：部署分支裁剪解决体积/显存；ClassLite52 是当前最好的
   延迟结构，但精度尚未达标。
