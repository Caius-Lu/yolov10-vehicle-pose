# 15% 结构化剪枝 + 100 epoch 恢复蒸馏：第一阶段结论

实验已在 `wsl-dev` 的 RTX 3090 Ti 上完整执行，训练用时 3.81 小时，未出现 CUDA OOM、非有限 loss 或重复任务。比较对象是此前完成的 200-epoch 640 baseline；验证集、输入尺寸和部署 benchmark 口径保持一致。

## 同口径结果

| 指标 | 200e baseline | 剪枝 + KD 100e | 变化 |
|---|---:|---:|---:|
| 参数量 | 4,005,986 | 3,350,666 | -16.36% |
| `best.pt` 大小 | 8,422,070 B | 7,057,777 B | -16.20% |
| Box mAP50-95 | 0.66761 | 0.57041 | -0.09720 |
| Pose mAP50-95 | 0.51455 | 0.41532 | -0.09923 |
| PCK@0.05 | 0.66863 | 0.60902 | -0.05960 |
| PCK@0.10 | 0.85248 | 0.81319 | -0.03930 |
| NME（越低越好） | 0.05960 | 0.07291 | +0.01331 |
| fused FP16 latency | 5.7010 ms | 5.6819 ms | -0.0191 ms / -0.34% |

部署计时为 batch=1、640、one-to-one-only、Conv/BN fuse、FP16、100 次 warmup、每轮 1000 次、3 轮平均。不能把“剪枝模型自身从 FP32 切到 FP16 的 31.61% 加速”当作剪枝收益；真正的剪枝收益必须比较两个模型各自的 fused FP16，结果只有 0.34%。

## 训练曲线证据

- Box mAP50-95 在 epoch 14 达峰；
- Pose mAP50-95 在 epoch 24 达峰；
- PCK/NME 在 epoch 30–31 左右达峰；
- 训练 loss 此后继续下降，但验证指标平台化或回落。

因此问题不是“100 epoch 还不够”。继续盲目加 epoch 不具备证据基础。更可能的影响因素是：统一 15% 通道裁剪伤及对姿态敏感的 head/高分辨率路径，以及 `round_to=8` 得到的通道形状没有转化成 RTX 3090 Ti 上更高效的 kernel。

## 门禁结论

仅“物理参数至少减少 10%”通过。精度门禁和“FP16 latency 至少降低 10%”均失败，故该模型不进入部署推荐，200-epoch baseline 保持不变。

第二阶段只验证一个隔离候选：保护 Pose/Detect head 的敏感根层，采用分层剪枝率和更适合硬件的通道对齐，并对 KD 权重做有限调度。先评估剪枝初始化和小 epoch 趋势；只有精度方向改善且实测 latency 有方向性收益，才进入正式恢复训练。
